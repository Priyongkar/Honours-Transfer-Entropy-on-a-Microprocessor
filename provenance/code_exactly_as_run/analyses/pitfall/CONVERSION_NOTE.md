# Pitfall conversion: what was done and what was found (4 November 2026)

Source: `~/6502-information-flow/data/raw/Pitfall/Pitfall/` (Wang et al. 2023 format; eight contiguous
windows, zero state differences at every join), 3,510 transistor states at 30,720 sub-steps.
Script: `convert_pitfall.py`. Output: `data/raw/pitfall.ts.spikes.npy` (1,018 x 3,510 uint8, Donkey
Kong layout), `data/raw/pitfall_states_by_phase.npy`, `output/conversion_checks.json`,
`output/pitfall_groups.npz`. No transfer-entropy statistic computed.

## Same format as Donkey Kong (verified)
- Layout: rows x transistors, uint8, an entry = a change of state in either direction, three rows per
  clock phase with events on the first row; the main run's reduction (stride 3, phase with most
  events, crop) returns the constructed events exactly.
- Column mapping: netlist order; all 62,133 pairs of active transistors sharing a gate node fall in one
  group, no shared gate node split (Donkey Kong: 62,387, none split); random pairs 3.7 %.
- Time base: the clock nodes cp1 and cclk switch every 90 sub-steps, so one phase = three file steps
  of 30 (as one phase = three Donkey Kong rows). Sampled at sub-step 60 of each 90, the end of the
  quiet interval before the clock edge. Clock group: 456 transistors (Donkey Kong 456), changing in
  99.7 % of samples (Donkey Kong 98.95 %).
- Coding constructed from states (not inferred); 3,260 of 250,518 transistor-phases with activity
  have an even number of changes and so show no event (1.3 %).

## Differences that matter
1. **Length: 340 phase samples** (Donkey Kong 133,926). An earlier statement of 1,024 samples was
   wrong: it counted thirds of a phase.
2. **Phase structure: 51 of 286 groups locked (all strictly)**, Donkey Kong 445 of 519. Cause: activity
   comes in two large bursts per phase, at the clock edge and 30 sub-steps later; 180 groups change in
   the first burst in one phase and in the second burst in the other, so they change once in every
   phase. In Donkey Kong nearly all activity falls on one row per phase. The second burst is
   consistent with external inputs (memory, TIA) arriving one step after the edge in this simulator;
   not verified.

## Update (4 November 2026, afternoon): the authors' simulator reproduces the recording exactly

The original Pitfall and Space Invaders recordings are no longer downloadable (the authors' S3
bucket returns 403 for every file, including Donkey Kong; no mirror found). The simulator they used,
Sim2600 (Visual6502.org, CC0, github.com/ericmjonas/Sim2600, commit f719877), includes the ROMs.
Ported to Python 3 in `vendor/Sim2600` (lib2to3; pickle encoding latin1; relative imports; ROM bytes;
Cython build via `setup_py3.py`). Recorder: `record_game.py`.

- The first 2,990 regenerated Donkey Kong rows match `donkeykong.5000.ts.spikes.npy` in all
  10,494,900 entries, with change coding (state after half-clock i+1 differs from after i).
  Turn-on coding gives 386,469 mismatches. **The change coding inferred in the thesis is
  confirmed at source.**
- Speed 0.9 ms per TIA half-clock; full-length (639,999-row) recordings of Donkey Kong (to check the
  whole file), Pitfall and Space Invaders started in the background (`run_regen.sh`).
- The Wang et al. Pitfall data (340 phases) is superseded as a replication by these recordings.

## Full-length check (4 November 2026)

Each 639,999-row recording took about 7.5 minutes. The regenerated Donkey Kong recording is identical to
the published file in every entry of rows 0 to 401,775 (1.41 billion entries). Published row 401,776
holds 1,437 events where the simulation has none (the regenerated run has events on rows 401,772,
401,775, 401,778 …, every third row as before), and every later published row is zero. The published
recording was therefore truncated, with one anomalous final row, not silent. Row 401,776 lies at offset 1
of its three-row block, so the main run's reduction (offset 0) never used it; the 133,926 analysed
samples are all in the identical part. Pitfall (`data/regen/pitfall.regen.ts.spikes.npy`) and Space
Invaders (`data/regen/spaceinvaders.regen.ts.spikes.npy`) were generated by the same code; no statistic
has been computed on them.
